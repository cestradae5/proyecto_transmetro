# Ridership by parada (stop), not by station

Branch `feat/parada-ridership` (based on `feat/user-web`). Moves passenger counting, the 150% capacity alert and bus stops from `tbl_estacion` to `tbl_parada`; a station is a parada that also has a `tbl_estacion` row (1:1). Supersedes the station-anchored parts of `ridership-capacity.md` (S1, S3, S7, S8, S9) and `user-web.md` (S4, S10).

## Specs
- S1 (user, verbatim): "En el simulador de talanquera también deben de aparecer también todas las paradas con sus lineas paradas (las que son estaciones también deben de aparecer)".
- S2 (user, verbatim): "Lo del 150% son para las paradas y estaciones, recuerda que las hay paradas que se convierten en estacion, el conteo es por parada(estacion)." The count, capacity and alert belong to the parada; a station's numbers are its parada's.
- S3 Capacity: `tbl_parada.capacidad_pasajeros INTEGER NOT NULL DEFAULT 100 CHECK (> 0)`. Existing DBs: each parada that has a station takes the station's `capacidad_pasajeros` once, then `tbl_estacion.capacidad_pasajeros` is dropped. Parada create/update accept optional `capacidadPasajeros` (integer >= 1; null -> 400) and every parada response returns it; station requests/responses no longer have it.
- S4 Events and stops by parada: `tbl_evento_talanquera.id_parada` and `tbl_parada_unidad.id_parada` (NOT NULL, FK `tbl_parada`) replace `id_estacion`; existing rows are converted through `tbl_estacion.id_parada`. `tbl_alerta` gains nullable `id_parada_origen` (FK); existing capacity alerts are backfilled from `id_estacion_origen`. Re-applying `init.sql` changes nothing more.
- S5 Turnstile: body `{ numeroTarjeta, idParada, tipo, idempotencyKey? }` (replaces `idEstacion`); response `parada` (replaces `estacion`) = `{ idParada, nombreParada, idEstacion | null, capacidadPasajeros, personasEnParada, porcentaje, alertaActiva }`. Unknown parada -> 404 "Parada con ID <id> no existe.". Fare, idempotency and every other rule unchanged.
- S6 Alert: after an `ENTRADA`, `personasEnParada >= 1.5 x parada.capacidad_pasajeros` and no non-`RESUELTA` capacity alert for that parada -> one `CAPACIDAD_ESTACION` alert, `ESTACION -> CENTRAL`, `id_parada_origen` = parada, `id_estacion_origen` = its station or NULL, no unit, no author.
- S7 Bus stop: `POST /operations/ridership/units/:id/arrival` `{ idParada }`; departure and all occupancy rules unchanged, now per parada.
- S8 Readings: `GET /operations/ridership/stops/:id` (replaces `stations/:id`) returns the S5 `parada` object; `GET /operations/ridership/units/:id` open stop carries `idParada`, `nombreParada`, `idEstacion`; `GET /operations/ridership/alerts` items carry `parada: { idParada, nombreParada, idEstacion }` (replaces `estacion`).
- S9 Citizen lines: `GET /citizen/lines` (replaces `/citizen/stations`, no auth) -> `[{ idLinea, numeroLinea, nombreLinea, paradas: [{ idParada, nombreParada, orden, esEstacion }] }]`: `ACTIVA` lines by number, their `ACTIVA` paradas in route order; then, if any, a last group `{ idLinea: null, numeroLinea: null, nombreLinea: "Sin línea", paradas }` with `ACTIVA` paradas on no `ACTIVA` line (by name, `orden: null`), so every active parada appears.
- S10 SPA simulator: the select groups paradas by line (`<optgroup label="Línea N - nombre">`; "Sin línea" last); a station shows "(estación)" after its name; a parada on two lines appears in both with the same value. Sends `idParada`; shows "Personas en la parada: N".
