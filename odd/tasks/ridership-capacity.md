# Ridership: station and bus occupancy (R14, R15)

Branch `feat/ridership-capacity`. Turnstile (talanquera) events give station occupancy; bus occupancy is an estimate per stop. Step 1 of 3 (L5): backend only, tested with Postman; user SPA and QPayPro come later.

## Specs
- S1 (user, verbatim): "Los buses tienen una capacidad máxima de pasajeros, por lo que en el momento que una estación tiene por lo menos un 50% más de su capacidad genera una alerta para que otro bus llegue." Capacity is the station's own (user: "Si es la capacidad de la parada(estacion)"), threshold 150% (user: "si es 150%"): `personasEnEstacion >= 1.5 x tbl_estacion.capacidad_pasajeros` -> one alert. No second alert for the station while one is not `RESUELTA`. Factor is a named constant.
- S2 (user, verbatim): "15. Si un bus no llena el 25% de su capacidad, deberá esperar 5 minutos más en cada estación." On arrival at a station, if the estimated occupancy after boarding is `< 0.25 x tbl_unidad.capacidad_pasajeros` -> `minutosEsperaExtra = 5`, else `0`.
- S3 Station capacity: `tbl_estacion.capacidad_pasajeros INTEGER NOT NULL DEFAULT 100 CHECK (> 0)`, added idempotently for existing DBs; station create/update API accepts optional `capacidadPasajeros` (positive integer) and every station response returns it.
- S4 Turnstile (user idea, verbatim: "Mi idea es contar solo las entradas y salida desde las paradas e ir sumando y restando aunque nos ea muy presiso"): `POST /operations/ridership/turnstile` `{ numeroTarjeta, idEstacion, tipo: "ENTRADA" | "SALIDA" }`. Every accepted pass stores one append-only `tbl_evento_talanquera` row; no mutable counter. The client never sends balance (decision L4): the server reads and deducts `tbl_tarjeta_ciudadana.saldo`.
- S5 Fare: `ENTRADA` requires an `ACTIVA` card with `saldo >= TARIFA_PASAJE` (Q1.00 constant) and deducts it in the same transaction as the event. `SALIDA` requires an existing card, charges nothing and ignores card state. Unknown card -> 404; card not `ACTIVA` on entry -> 409; insufficient balance -> 409; unknown station -> 404; invalid body -> 400. Every rejection leaves balance, events and alerts unchanged.
- S6 Turnstile access (decision L4): no user login. Disabled unless env `TURNSTILE_SIMULATOR_ENABLED=true` (-> 404 otherwise); requires header `X-Turnstile-Key` equal to env `TURNSTILE_API_KEY` (-> 401 otherwise). CORS allows the header.
- S7 Station occupancy: `personasEnEstacion = ENTRADA events at the station - passengers who boarded buses there` (exits are passengers leaving buses, not waiting people), never below 0. Evaluated for S1 after every accepted `ENTRADA`.
- S8 Bus stop: `POST /operations/ridership/units/:id/arrival` `{ idEstacion }` opens a stop: boards `min(waiting, free seats)`, evaluates S2 and returns it. `POST /operations/ridership/units/:id/departure` closes the open stop: `bajaron = min(SALIDA events at the station since arrival, occupancy the bus arrived with)`, then boards the newly waiting up to capacity. Occupancy carries from the unit's last closed stop (0 if none), always within `0..capacidad`. Arrival with an open stop -> 409; departure without one -> 409; unknown unit/station -> 404. Permission `FLOTA_GESTIONAR` (same as unit location reporting).
- S9 Readings (`ALERTAS_OPERATIVAS_GESTIONAR`): `GET /operations/ridership/stations/:id` -> `{ idEstacion, nombreEstacion, capacidadPasajeros, personasEnEstacion, porcentaje, alertaActiva }`; `GET /operations/ridership/units/:id` -> `{ idUnidad, numeroPlaca, capacidadPasajeros, ocupacionEstimada, porcentaje, paradaAbierta }`; `GET /operations/ridership/alerts` -> station capacity alerts, newest first.
- S10 System alerts (user chose option 1: "si vamos con el paso 1 con id_emple opcional"): `tbl_alerta.id_empleado` becomes nullable. The S1 alert is `tipo_alerta=CAPACIDAD_ESTACION`, `tipo_origen=ESTACION`, `tipo_destino=CENTRAL`, `id_estacion_origen` = station, no unit, no author. Alert DTO `autor` is `null` for it. Existing unit -> station alerts, inbox, central view and history keep working unchanged; capacity alerts advance with the existing `PATCH /operations/alerts/central/:id/status`.
